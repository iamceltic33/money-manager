# Локальный API обязательств

Экспортируется из `@/entities/obligation`. Пользователь задаётся явно через `userId`; все чтения и изменения ограничены этим аккаунтом. Интерфейс и прогноз пока не подключены.

## Создание и изменение

`createLocalObligation` принимает `userId`, `name`, необязательный `categoryId`, `firstPaymentDate`, `lastPaymentDate` и один из режимов:

- `paymentMode: 'fixed'`, `monthlyAmount`, `paymentDay` (1–31): создаёт обязательство и все платежи в пределах дат одной транзакцией.
- `paymentMode: 'manual'`: создаёт обязательство без предположений о суммах и без автоматических платежей.

Даты — локальные календарные строки `YYYY-MM-DD`. Суммы нормализуются до двух знаков по существующему правилу операций. Для фиксированного режима в заданном сроке должна существовать хотя бы одна дата платежа.

`updateLocalObligation` принимает тот же полный набор значений и `id`. Отсутствующий `categoryId` сохраняет прежнюю категорию, NULL снимает её. При смене суммы, дня или срока фиксированного обязательства неоплаченная часть пересоздаётся. Оплаченные месяцы сохраняют дату, сумму, ID и связь с расходом; исключить их из срока нельзя. Одна ошибка откатывает обязательство, платежи и задания удаления вместе. Простое изменение названия/категории расписание не пересоздаёт.

Режим существующего обязательства пока нельзя переключать: нужен отдельный сценарий, чтобы не потерять введённые вручную суммы. Архивирование/досрочное завершение с оплаченной историей остаётся следующей доработкой.

## Ручное расписание

- `createLocalObligationPayment({ userId, obligationId, dueDate, amount })`: добавляет месяц для ручного режима.
- `updateLocalObligationPayment({ userId, id, dueDate, amount })`: меняет неоплаченный ручной платёж в том же календарном месяце.
- `deleteLocalObligationPayment(userId, id)`: удаляет неоплаченный платёж и сохраняет задание для облака. Для нового месяца создаётся отдельный платёж.

На один месяц одного обязательства допускается один платёж. Разные месяцы могут содержать любые положительные суммы. Пропущенные месяцы не заполняются автоматически.

`getMonthlyPaymentId` создаёт UUID v8 из SHA-256 ID обязательства и календарного месяца. Один месяц получает одинаковый ID при пересчёте и на разных устройствах; фактический день месяца не влияет на идентичность. Сам по себе генератор не создаёт записи.

## Оплата, удаление и чтение

`linkLocalObligationPayment(userId, id, transactionId)` привязывает существующий расход или отвязывает его при NULL. База проверяет владельца, тип операции и уникальность связи. Перед заменой уже связанного расхода требуется явная отвязка. Связь не создаёт новую операцию, не меняет её сумму/дату/флаг исключения и не списывает баланс повторно. Исключение таких расходов из среднего прогноза будет добавлено в этапе расчётов по связи, без перезаписи пользовательского флага.

`deleteLocalObligation(userId, id)` удаляет обязательство и неоплаченные платежи атомарно. При наличии оплаченных месяцев возвращает ошибку; фактические расходы никогда не удаляются этим API.

Чтение: `getLocalObligations(userId)`, `getLocalObligationById(userId, id)`, `getLocalObligationPayments(userId, obligationId?)`. Чужой ID не раскрывает запись. Список платежей отсортирован по дате.

Мутации удерживают защиту от перезапуска приложения до завершения транзакции. Общая очередь локальных записей также защищает обычные операции/категории и входящий снимок; сеть не удерживает очередь. Перед добавлением интерфейса следует подключить обновление его состояния после мутаций/синхронизации.

## Проверено

5 тестов API: календарные границы и високосные месяцы, нормализация/баланс, откат, сохранение оплаченных месяцев, переменные суммы, связи/аккаунты и параллельный обычный расход при ошибке расписания. Дополнительно 8 сценариев синхронизации и 3 интеграционных PostgreSQL-теста. Тесты используют SQLite Node.js и отдельный PostgreSQL; проверка на устройстве остаётся открытой.


### Сохранение расхода с платежом

`createLocalTransaction` и `updateLocalTransaction` принимают необязательный `obligationPaymentId`:

- строка — связать расход с указанным существующим платежом (и снять прежнюю связь);
- `null` — убрать связь;
- `undefined`/отсутствие — сохранить прежнюю связь при редактировании.

Запись расхода, снятие старой связи, установка новой и пометка обязательств для синхронизации выполняются одной SQLite-транзакцией. Чужой, удалённый или занятый платёж отменяет всю запись; связь допускается только с расходом. Плановые сумма и дата, а также флаг расхода `exclude_from_average` от связывания не меняются.
