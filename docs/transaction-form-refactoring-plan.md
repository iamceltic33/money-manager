## Цель

При переключении «Расход» ↔ «Доход» сохраняются сумма, дата и заметка. Пользователь остаётся в одном экране с одним экземпляром формы. Поле суммы и клавиатурный контейнер не размонтируются при смене типа.

Обычный ререндер при изменении типа допустим. Отдельная оптимизация количества рендеров через `memo` не является условием сохранения полей и выполняется только при обнаруженной проблеме производительности.

Этот рефакторинг предшествует замене кнопок на главной. Плавающая кнопка «+», удаление текущих кнопок с главной и изменение нижней навигации в этот план не входят.

## Что обнаружено в текущем коде

- `OperationSwitcher` вызывает `router.push('/add-expense')` или `router.push('/add-income')`.
- В `(operations)/_layout.tsx` переключатель расположен над стеком отдельных экранов.
- Расход и доход создают разные экземпляры `TransactionForm`; каждый хранит собственные состояния полей через `useState`.
- Значения `defaultValues` применяются при создании формы. Изменение начальных значений само по себе не должно сбрасывать введённые поля.
- Для расхода с `paymentId` сначала загружаются данные платежа, затем форма получает сумму, категорию и связь с платежом. Используется `key={paymentId ?? 'ordinary'}`.
- Выбор кредитного платежа внутри формы может менять сумму и категорию.
- Обработчики сохранения сейчас перехватывают ошибку и возвращают успешно завершённый Promise. При введении явного сброса черновика нужно отличать ошибку от успешного сохранения.
- Редактирование существующей операции использует ту же `TransactionForm` и должно сохранить текущее поведение.

## Контракт черновика

| Значение | При переключении типа |
| --- | --- |
| Строка суммы `amountText` | Сохраняется точно, включая промежуточный ввод и десятичный разделитель |
| Дата | Сохраняется |
| Заметка | Сохраняется без обрезания пробелов во время ввода |
| Категория | Сбрасывается при реальной смене типа |
| Связь с платежом | Убирается при переходе на доход; при возврате на расход автоматически не восстанавливается |
| «Не учитывать в прогнозе» | Сохраняется как настройка расхода в пределах текущего черновика; для дохода не показывается и не отправляется |
| Тип | Меняется без смены маршрута и без добавления экрана в стек |

- Повторное нажатие уже выбранного типа ничего не сбрасывает.
- При переходе с расхода, связанного с платежом, на доход сумма сохраняется, но создаваемый доход не связывается с кредитом.
- Начальный `paymentId` применяется один раз при создании черновика. Возврат к типу «Расход», фоновая синхронизация и повторный рендер не применяют его заново.
- Во время сохранения блокируются повторное сохранение и переключение типа. Отправляется снимок значений с типом на момент нажатия.
- Ошибка сохранения оставляет черновик и текущий экран доступными для повторной попытки.
- Успешное сохранение завершает черновик и возвращает в исходный экран по существующему контракту навигации.
- Закрытие экрана добавления завершает черновик; новое открытие начинает новый. Изменение типа внутри открытой формы не считается закрытием.
- Черновик живёт только в памяти текущего экрана. Постоянное хранение в SQLite, Supabase или общем глобальном store не требуется.
- Форма редактирования не получает переключатель типа операции.

## Результат шага 5 (23 октября 2026)

## Критерии готовности

- Для добавления используется один экран и один экземпляр формы.
- Переключение типа сохраняет сумму, дату и заметку без повторной инициализации.
- Несовместимая категория и связь с платежом не попадают в операцию другого типа.
- Сохраняется точность суммы; используется существующий парсер, без промежуточного преобразования строки в число при смене типа.
- Повторное нажатие типа ничего не очищает; во время сохранения переключение заблокировано.
- Ошибка не удаляет черновик; новое открытие после закрытия или успеха не показывает старые значения.
- Старые ссылки и возврат работают, дополнительные экраны в стеке не накапливаются.
- Редактирование и нативное поведение клавиатуры сохранены.
- Автоматические результаты и визуальные проверки перечислены отдельно. Непроверенные сценарии не помечены выполненными.
