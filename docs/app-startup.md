# Запуск приложения

При холодном запуске существующий нативный splash остаётся видимым до восстановления сессии и загрузки локальных категорий и операций текущего пользователя. Основные экраны монтируются только после успешного завершения обеих загрузок, поэтому начальный баланс `0` не отображается как промежуточное состояние. Настоящий нулевой баланс пустого аккаунта отображается штатно.

Если сессии нет, splash скрывается после появления интерфейса входа. На web и при повторной загрузке данных после входа используется экран «Загрузка данных…».

При ошибке локальной инициализации splash скрывается и отображается экран «Не удалось загрузить данные» с кнопкой «Повторить». Повторная попытка повторно загружает неинициализированные хранилища; ошибка открытия SQLite или миграции сбрасывает кэш подключения. Операции не удаляются.

Синхронизация с облаком начинается после успешной локальной инициализации и не входит в ожидание splash. Её ошибки показываются отдельно; локальные данные доступны без сети. На новом устройстве без локальных операций данные из облака появятся после синхронизации.

Проверено: TypeScript, ESLint, 25 тестов запуска, синхронизации и защиты перезапуска. Тесты запуска используют подмены React hooks и платформенных API; они проверяют переходы состояний, а не реальную отрисовку Android/iOS. Нативное скрытие splash и внешний вид требуют проверки холодного запуска установленного release APK, в том числе без сети.

Команда тестов:

```sh
node --test tests/startup.test.cjs tests/sync.test.cjs tests/restart-guard.test.cjs
```
