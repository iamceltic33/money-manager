# Проверка изоляции Supabase

Проверено 17 сентября 2026 года на подключённом облачном проекте.
Для `categories` и `transactions` RLS включён; фактические политики совпадают
с миграцией `20260825092738_initial_schema.sql`.

Созданы два временных аккаунта через Supabase Auth. Все проверки доступа
выполнены через `supabase-js` с публичным ключом приложения и отдельными
пользовательскими сессиями. Серверный ключ не использовался.

Результат: **62 проверки прошли**, изменения политик не потребовались.

Для каждого аккаунта проверены:

- Создание, чтение, изменение и удаление своих категорий и операций.
- Чтение списка без фильтра по владельцу: возвращаются только свои записи.
- Чтение, изменение и удаление чужой записи по известному ID: возвращается пустой результат; запись владельца не изменяется.
- Создание записи от имени другого пользователя и смена `user_id`: ошибка RLS `42501`.
- Перезапись чужой категории или операции через `upsert`: ошибка `42501`.
- Создание операции с чужой категорией и замена категории существующей операции на чужую: ошибка `42501`; прежняя связь сохраняется.
- Создание операции без категории разрешено.
- `get_current_balance` учитывает только операции текущего аккаунта.
- Удаление своей категории сохраняет операцию и обнуляет `category_id`.

Без авторизации категории и операции не видны, вставка отклоняется.

После проверки оба временных аккаунта удалены. Контрольный запрос подтвердил
отсутствие их профилей, категорий и операций.

Это проверка облачного API и RLS. Локальная изоляция SQLite, переключение аккаунтов
в интерфейсе и будущая синхронизация в эту проверку не входили.
